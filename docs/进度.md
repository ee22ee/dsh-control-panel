## 二、决策日志

### D1 · 目标框架 net10.0-windows
- 本机 SDK 10.0.403 + `Microsoft.WindowsDesktop.App 10.0.14` 已装；.NET 8 于 2026-11-10 结束支持。
- **回滚**：改 `csproj` 的 `<TargetFramework>` 为 `net8.0-windows`，代码无需改动。

### D2 · 无边框窗口 + 单个铺满的 WebView2
- 消灭旧版「WinForms 自绘外壳 + WebView2 内容区」双轨渲染带来的 P6/P10/P11/P12/P24/P25 六条坑。
- **回滚**：不可回滚（重写的核心决策）。

### D3 · WebView2 走 NuGet 而非旧 `lib/`
- 旧 `lib/` 三个 dll 是 net462 版，net10 无法引用。

### D4 · NuGet 用本地源 + node 下载
- `dotnet restore` 访问 api.nuget.org 报 `NU1301 SSL 握手失败 / 安全包中没有可用的凭证`；node 走 OpenSSL 能连通。
- 写 `fetch-nupkg.mjs` 用 node 抓 nupkg 到 `packages/`，`nuget.config` 清空远程源只留本地。
- **回滚**：网络恢复后删掉 `nuget.config` 的 `<clear />`。
- **注意**：这是本机环境绕行，不是标准做法。

### D5 · 关掉 WinForms 自动缩放
- PerMonitorV2 下 `AutoScaleMode.Font` 会二次缩放 Bounds（1075 宽被撑到 1580、超出屏幕），与 P2/P3 同源。
- 决策：`AutoScaleMode = None`，DPI 完全交给 WebView2 的 `RasterizationScale`。
- **回滚**：无。

### D6 · 窗口尺寸按物理像素给
- 本机 3072×1920 物理 / 200% 缩放。按逻辑像素设 1400 上限 → 物理只 1400 宽 = 700 CSS px。
- 决策：`WorkingArea`（物理）的 74%×84%，只设下限不设上限。修后视口 1137×766。

### D7 · 日志写入带回退链 + 失败诊断
- 沙箱内写 `%LOCALAPPDATA%\DshPanel2\panel.log` 报 `Access denied`。
- 决策：`%LOCALAPPDATA%` → exe 同级，任一失败都写 `panel.log.failure` 记录真实异常。

### D8 · `Paths.ExeDir()` 直接用 `AppContext.BaseDirectory`
- **踩坑**：最初多套了一层 `Path.GetDirectoryName`，导致配置和日志落到 `bin/Debug` 而不是 exe 所在目录。
- 修正后配置/数据目录都正确落在 `bin/Debug/net10.0-windows/`。
- **教训**：`AppContext.BaseDirectory` 本身就以分隔符结尾，不需再取父目录。

### D9 · 用 CDP 远程调试做 UI 验证
- `DSH_PANEL_DEBUG=1` 时给 WebView2 加 `--remote-debugging-port=9223`。
- `scripts/cdp.mjs` 支持 `eval` / `click` / `dom` / `shot`，用 node 内置 `fetch` + `WebSocket`。
- **价值**：屏幕截图受窗口位置、DPI 虚拟化、其它窗口遮挡影响，CDP 直接拿页面像素和 DOM 矩形，是目前唯一可靠的 UI 验证手段。

### D22 · 单实例保护修复（严重 bug，已实测）
**现象**：用户双击快捷方式后界面变成「面板界面无法加载 / 0x8007139F」。

**根因链**：
1. `Program.TryFocusExisting()` 用 `FindWindow(null, "DSH 面板")` 匹配窗口标题；
2. 但窗口标题实际取自配置（默认「蓝色大肥鱼 · DSH 控制台」）→ **永远匹配不到**；
3. → 每个实例都判定自己是「孤儿 Mutex」继续启动；
4. → 多个进程同时初始化 WebView2、抢同一个 `WebView2Data` 用户数据目录；
5. → 后启动的报 `0x8007139F ERROR_INVALID_STATE`，界面变错误页。
   现场实测同时有 **3 个 DshPanel2.exe** 在跑。

**修法**：不看窗口标题，改为 `Process.GetProcessesByName` 判断有没有同名进程；
有就唤起并退出，没有才当孤儿 Mutex 接管。查不到进程列表时返回 false（宁可多开也不误拒）。

**实测**：连开三次，进程数稳定为 1，后两次日志均为「已有面板实例在运行（PID xxxxx），本次启动退出」。

### D24 · 截图工具有 DPI bug（不是应用问题）
- 现象：所有截图里面板窗口都偏右、右侧被裁，一度误判为「卡片/按钮溢出」。
- 根因：`screenshot.ps1` 未声明 DPI 感知，进程是 DPI-unaware：
  `Screen.Bounds` 报逻辑尺寸 1536×960，而 `CopyFromScreen` 按物理像素抓取
  → **只截到屏幕左上角 1/4**（物理 1536×960），右半边全丢。
- 实测对照：`GetWindowRect` 显示窗口 `L=200 W=1137`，屏幕 1536×960，**窗口本来就居中且完整**。
- 修法：脚本开头 `SetProcessDPIAware()`，并用 `SystemInformation.VirtualScreen` 取全屏；
  现在输出 3072×1920 完整物理分辨率。

### D28 · 中文路径导致图标全部失效（本轮最大发现）
用户报告「托盘里看不到面板图标」，排查过程与结论：

**对照实验**（同一脚本，只换图标来源）：

| 测试 | 图标来源 | 结果 |
|---|---|---|
| A | `SystemIcons.Application` | ✅ 托盘显示 |
| B | `new Icon("...\DSH插件\...ico", 32, 32)` | ❌ 托盘**不显示**（对象创建成功、无异常） |
| C | 从 exe 提取 + `ToBitmap()/GetHicon()` 缩放 | ⚠️ 显示但是**灰块**（GetHicon 丢 alpha） |
| D | ico 复制到 `%TEMP%`（ASCII）再 `new Icon(...)` | ✅ 托盘**彩色正常** |

**结论**：中文路径 + `new Icon(path, w, h)` 产生的句柄会被 Shell 拒绝，
**而且全程不抛异常**——日志只能证明「我们设了 Visible=true」，不能证明 Shell 接受了。

**修法**（`TrayManager.ApplyIcon` 三级降级）：
1a. ico 已在 ASCII 路径 → 直接加载（最优）
1b. ico 在非 ASCII 路径 → 复制到 `%TEMP%` 再加载（文件名带 PID，避免句柄占用）
2.  `Icon.ExtractAssociatedIcon(exe)` —— 能显示但丢 alpha，仅作兜底
3.  `SystemIcons.Application`

**踩坑**：`new Icon(file)` 会**一直持有文件句柄到 Dispose**，用固定临时文件名时第二次启动
必然报 `Access to the path is denied`（我一开始误判成沙箱限制）。

### D32 · 部署时**绝不**用 `taskkill /T`
`taskkill /PID <面板> /T /F` 会连子进程树一起杀 —— 面板启动的 DSH 服务是它的子进程，
于是「关面板」变成「把正在用的 DSH 服务和网页一起打死」（本次实测踩到，用户的 Web GUI 直接断线）。

- **正确做法**：只 `taskkill /PID <pid> /F`，不带 `/T`。
- 部署前先确认父子关系：`Get-CimInstance Win32_Process -Filter "Name='DshPanel2.exe'" | Select ProcessId,ParentProcessId`，
  再看 3080 那个 node 的父进程是不是面板 —— **不是**才允许继续。
- 反过来：如果面板**不**是该服务的父进程，杀面板对服务零影响（本次实测：杀面板后 3080 仍 LISTENING）。
- 额外发现：`cp` 覆盖运行中的 `DshPanel2.dll` 会 `Device or resource busy`。前端资源内嵌在 **dll** 里，
  exe（apphost）在代码不变时哈希不变、不需要替换 —— **只换 dll 就够**，判断依据 `md5sum dist/DshPanel2.exe`。
- **改名法部署**（面板还开着也能更，实测有效）：`mv 旧.dll 旧.dll.bak-<时分秒>` 再 `cp 新.dll 目标`。
  Windows 允许给被映射的文件改名、不允许覆盖；运行中的进程继续用已映射的旧映像，下次启动即新版。

### D35 · 「确认重启」的展开/收回做成真过渡（用户反馈 #5）
第一版是瞬间切换（`display:none` + `width` 硬变），抖得很生硬。改成三个按钮同步做 flex 过渡：

**关键点是三处都不能用 `display:none`**，否则某一项会先瞬间占位、下一帧才开始动画（实测出现「主按钮先撑大到 232px 再缩到 46px」的抽动）：

| 元素 | 收起 → 展开 | 做法 |
|---|---|---|
| 主按钮 | 176px → 46px | `.btn.big` 用 `flex: 1 1 0`（basis 从 0 起才可插值）→ `.compact` 的 `flex: 0 0 46px` |
| 重启图标 | 46px → 0 | `.icon.collapse` 收宽度 + `margin: 0 -5px` 抵掉前后各 10px 的 gap |
| 确认按钮 | 0 → 186px | `.confirm-restart` 常驻 DOM，靠 `flex-grow` 0→1 + opacity/padding 过渡 |

**踩到的一个坑**：文字即使 `opacity:0` 仍占宽度，会把收缩态里的图标挤出 `overflow:hidden` 的可视区
（现象：红方块里什么都没有）。所以 `.compact .btxt` 必须同时 `max-width: 0`。
另外图标一开始用 1.8px 描边的空心方块，缩到 46px 按钮里几乎看不见 —— 改成 `fill` 实心，`height:22px`。

**实测（CDP 逐帧采样）**：
```
展开  176 → 169 → 116 → 70 → 53 → 47 → 46  （约 270ms）
收回   46 →  51 →  96 → 149 → 168 → 175 → 176
```
曲线单调、无回弹、无跳变。

**「按钮间隙不等」（用户反馈 #6）**——两个独立的坑叠在一起：
1. `.btns` 用 `gap: 10px`，而中间那个 0 宽的「确认重启」**仍然白占一个 gap**，
   于是「主按钮 → ⟳」= 10px、「⟳ → 🌐」= 20px。改成相邻 `margin-left`，
   收起的项自己把 `margin-left` 归零（`.icon.collapse` / `.confirm-restart` 都是）。
2. `box-sizing: border-box` 下 `width: 0` **压不住 1px 边框**，那两个按钮收起来后各残留 2px。
   必须同时 `border-width: 0`。

实测三处间距：平时 `[10, 0, 10]`、确认态 `[0, 10, 10]`（0 是 0 宽元素自身的宽度差），
视觉上两个可见间距恒为 10px。

### D36 · 悬停别把红色按钮变灰（用户反馈 #7）
**根因是 CSS 特异性，不是颜色值本身**：

| 规则 | 特异性 | 结果 |
|---|---|---|
| `.btn:hover:not(:disabled) { background: var(--hover) }` | **(0,3,0)** | 两个伪类算三层 |
| `.btn.danger { background: var(--danger) }` | (0,2,0) | 常态才生效 |

悬停时 `--hover`（浅灰）盖掉了红底，白字直接糊成一片灰。`.btn.danger:hover:not(:disabled)`

修法：在 `.btn.danger:hover` 里**显式重写 `background: var(--danger)`**，并把变暗改成微提亮

`.btn.primary:hover` / `.btn.ghost:hover` 都显式写了 background，所以没踩这个坑——
**新增带底色按钮时，hover 规则必须连 background 一起写**。

### D38 · 切主题时所有控件必须同速
**现象**：切换明暗模式时各控件换色速度不一致，中间能看到「卡片已经变白、body 还在渐变」的混搭帧。

**根因**：颜色过渡分散在各处且时长不同 —— `body` .18s、`.nav` .12s、`.btn` .12s、`.sw i` .16s，
而卡片、标题栏、侧边栏背景、`.srow` 分隔线**根本没写** transition（瞬时切换）。五种速度混在一起。
**修法**：`applyTheme(dark)` 切换时给 `body` 挂 `.theming` 类 240ms，CSS 里
`body.theming, body.theming *` 用 `!important` 把所有元素的 transition 统一压成 `.16s`
（background-color / color / border-color / box-shadow 四条），窗口结束后摘掉 ——
hover、开关滑动、抽屉展开这些交互动画的原有节奏完全不受影响。

**两个必须保留的细节**：
1. **首帧直接落位**：`curDark === null` 时只切类、不挂 `.theming`，否则启动瞬间会从默认深色
   渐变到浅色，闪一下。
2. **去重**：`applyTheme` 在 `curDark === d` 时直接 return。不做去重的话，每 1.5 秒一次的 `state`
   推送会反复重开那 240ms 窗口，把用户正在做的 hover 也压成 .16s。

**验证**：把过渡临时放慢到 1.6s 抓中间帧（`shots/ui7-midframe.png`），整屏处于同一中间灰度、
卡片的明暗关系不变，没有任何区块超前或滞后；另用 `getComputedStyle` 逐一检查 13 个代表元素，
`transitionDuration` 全部是 `0.16s, 0.16s, 0.16s, 0.16s`。
